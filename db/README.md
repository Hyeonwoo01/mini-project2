# 데이터베이스 스키마 문서

본 문서는 '서울시 2030 카페 상권 분석' 프로젝트의 데이터베이스 구조를 설명합니다. 
데이터 파이프라인은 원본 수집 ➔ 기준 정보 ➔ 대시보드 집계의 3계층 아키텍처로 설계되었습니다.

* **데이터 기준시점**: 2026년 7월 15일(수) 기준 24시간 데이터

---

## 1. Raw 계층 (수집 원본 데이터)
외부 API 및 CSV에서 적재된 가공 전 순수 원본 데이터입니다.

### `raw_seoul_living_pop`
* **설명**: 서울시 열린데이터광장 API에서 수집한 24시간 행정동별 유동인구 데이터
* **입도**: 1행 = 1개 행정동의 특정 1시간 데이터
* **주요 컬럼**:
  * `region_code` (VARCHAR): 행정동 코드 (Index)
  * `base_date` (VARCHAR): 수집 일자 (YYYYMMDD)
  * `time_hour` (INT): 시간대 (0~23)
  * `pop_2030` (REAL): 2030세대 생활인구 합계 (단위: 명)

### `raw_resident_pop`
* **설명**: 서울시 주민등록인구 통계 (CSV 적재)
* **입도**: 1행 = 1개 행정동
* **주요 컬럼**:
  * `region_code` (VARCHAR): 행정동 코드 (PK)
  * `resident_2030` (INT): 2030세대 거주 인구수 (단위: 명)

### `raw_cafe_stores`
* **설명**: 서울시 상권 상가업소 정보 중 카페/커피숍 데이터 (CSV 적재)
* **입도**: 1행 = 1개 상가(카페)
* **주요 컬럼**:
  * `store_id` (VARCHAR): 상가 업소 번호 (PK)
  * `region_code` (VARCHAR): 행정동 코드 (Index)

---

## 2. Dimension 계층 (차원/매핑 테이블)
데이터 간의 결합을 돕는 기준 정보 테이블입니다.

### `dim_region_mapping`
* **설명**: 행정동 코드와 실제 구/동 이름을 매핑
* **입도**: 1행 = 1개 행정동
* **주요 컬럼**:
  * `region_code` (VARCHAR): 행정동 코드 (PK)
  * `gu_name` (VARCHAR): 시군구명 (예: 서초구)
  * `dong_name` (VARCHAR): 행정동명 (예: 반포본동)

---

## 3. Mart 계층 
수집된 Raw 데이터를 `build_mart.sql`을 통해 연산하여 대시보드(`app/`)에서 즉시 조회할 수 있도록 구성한 최종 데이터 셋입니다.

### `mart_cafe_blueocean_kpi`
* **설명**: 상권별 최종 블루오션 지수 및 주요 KPI 지표 산출 결과
* **입도**: 1행 = 1개 행정동 (대시보드 KPI 카드 및 바 차트 1:1 매핑)
* **주요 컬럼**:
  * `living_pop_2030` (REAL): 2030 일평균 생활인구 (단위: 명)
  * `resident_pop_2030` (REAL): 2030 거주인구 (단위: 명)
  * `activity_ratio` (REAL): 주간 활동 배율 [생활인구 / 거주인구] (단위: 배)
  * `cafe_count` (INT): 경쟁 카페 수 (단위: 개)
  * `pop_per_cafe` (REAL): 점포당 잠재고객 [생활인구 / 카페 수] (단위: 명)
  * **`blue_ocean_score` (REAL)**: 최종 블루오션 지수 [활동 배율 × 점포당 잠재고객] (단위: 점)

### `mart_hourly_pattern`
* **설명**: 행정동별 24시간 2030 유동인구 평균 흐름 패턴
* **입도**: 1행 = 1개 행정동의 1시간 (대시보드 선 그래프 1:1 매핑)
* **주요 컬럼**:
  * `region_code` (VARCHAR), `time_hour` (INT): 복합 PK
  * `avg_pop_2030` (REAL): 해당 시간대의 평균 유동인구 (단위: 명)
